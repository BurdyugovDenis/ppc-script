# Яндекс Директ + Метрика: ассоциированные конверсии

Скрипт объединяет статистику Директа и визиты Метрики в один XLSX.
Все настройки — в `.env`, запуск — через `run_in_pycharm.py`.

## Запуск в PyCharm

1. Откройте папку проекта и выберите интерпретатор Python 3.11 или новее.
2. В терминале PyCharm установите зависимости:

   ```bash
   python -m pip install -e .
   ```

3. Скопируйте `.env.example` в `.env`. Если `.env` уже заполнен, не заменяйте его.
4. Укажите токены, счётчики, логин Директа, цели и даты.
5. Откройте `run_in_pycharm.py` и нажмите **Run**.

Результат: `data/output/ГГГГ-ММ-ДД_ГГГГ-ММ-ДД_логин.xlsx`.
Повторный запуск за тот же период и логин заменяет этот файл.
Не публикуйте `.env`: в нём находятся токены.

## Настройки

Пример основных настроек:

```dotenv
YANDEX_METRIKA_TOKEN=ваш_токен_метрики
YANDEX_DIRECT_TOKEN=ваш_токен_директа
YANDEX_METRIKA_COUNTER_IDS=12345678,87654321
YANDEX_DIRECT_CLIENT_LOGIN=client-login
YANDEX_GOAL_IDS=123456789,987654321

RUN_MODE=run
DATE_FROM=2026-08-01
DATE_TO=2026-08-31
DATA_DIR=data

LOOKBACK_DAYS=90
DIRECT_CONVERSION_MODEL=AUTO
METRIKA_ATTRIBUTION_MODEL=LAST
INCLUDE_VAT=true
INCLUDE_ASSOCIATED_REVENUE=true
```

- Счётчики и цели перечисляются через запятую. Можно выбрать от 1 до 10 целей.
- Токены должны иметь доступ ко всем указанным счётчикам и рекламному аккаунту.
- `DATE_FROM` и `DATE_TO` включаются в отчёт. Последняя дата — не позднее вчерашнего дня.
- `LOOKBACK_DAYS=90` — история перед каждым целевым визитом, а не перед началом месяца.
- `DIRECT_CONVERSION_MODEL` — модель лидов и дохода Директа: `AUTO`, `LC`, `LSCCD` или `FCCD`.
- `METRIKA_ATTRIBUTION_MODEL=LAST` — последний переход для источников визитов Метрики.
- `INCLUDE_VAT=true` — расходы Директа с НДС.
  Не влияет на доход Директа: он запрашивается отдельно.
- `INCLUDE_ASSOCIATED_REVENUE=true` — добавить ассоциированный доход выбранных целей Метрики.

Технические параметры обычно не нужны: `DIRECT_CHUNK_DAYS=31`,
`POLL_SECONDS=10`, `MAX_WAIT_MINUTES=60`,
`CLEAN_METRIKA_LOG_AFTER_DOWNLOAD=true` уже заданы по умолчанию.
Если они остались в вашем `.env`, они продолжают работать.

### Режимы запуска

| RUN_MODE | Действие |
| --- | --- |
| `run` | Скачать недостающие или несовместимые данные и собрать XLSX |
| `build` | Пересобрать XLSX из сохранённых TSV, без запросов к API |
| `goals` | Показать ID и названия целей всех выбранных счётчиков |
| `extract` | Только скачать исходные данные, без сборки отчёта |

Чтобы узнать ID целей, запустите `RUN_MODE=goals`, перенесите нужные ID в
`YANDEX_GOAL_IDS` и верните `RUN_MODE=run`.

## Что входит в XLSX

- `Сводка` и `Справка` — параметры, контрольные итоги и определения столбцов.
- `Источники`, `Кампании`, `Группы`, `Ключи`, `Типы площадок`,
  `Площадки`, `Полный срез` — рекламные срезы с KPI.
- `Основные пути` и `Роль каналов` — цепочки и позиции каналов в них.
- `Ассисты каналов` и `Цепочки конверсий` — детализация ассистов.

Заголовки русские, числа отображаются с одним знаком после запятой.
Десятичный разделитель зависит от локали Excel. Полное описание формул
находится на листе `Справка`.

## Логика расчёта

- **Директ:** показы, клики, расходы, лиды и доход берутся из Reports API.
- **Метрика:** целевые визиты и история касаний берутся из Logs API.
  Один визит с несколькими выбранными целями — один лид.
- **Связь визитов:** внутри одного счётчика по `counterUserIDHash`;
  если он пуст, используется `clientID`. Счётчики не склеиваются между собой.
- **Ассист Директа:** целевой визит не отнесён к Директу по выбранной
  модели Метрики, но до него у того же посетителя был визит из Директа
  или «Директ: Не определено» в пределах `LOOKBACK_DAYS`.
  Будущие визиты исключены. На уровне источника целевой визит учитывается один раз.
- **Сопоставление с Директом:** ID кампании и группы, нормализованный текст
  условия показа, тип и название площадки. Без кампании ассист остаётся
  на уровне источника. Надёжного ID условия показа в логах нет для каждого визита.
- **Пути:** одна цепочка на целевой визит. На листе `Основные пути`
  соседние повторы каналов схлопываются, на листе `Роль каналов`
  каждый визит считается отдельным касанием.
- **KPI:** CR = лиды / клики × 100%, CPL = расход / лиды.
  Считаются отдельно для лидов Директа, лидов Метрики и суммы
  «лиды Метрики + ассоциированные». Лиды Директа в эту сумму не входят.
  Коэффициент ассоциированности = ассоциированные / обычные лиды Метрики.
- **Доход:** ДРР = расход / доход Директа × 100%;
  ROMI = (доход Директа − расход) / расход × 100%.
  Себестоимость и другие затраты не учитываются. При нулевом знаменателе — пусто.

Полные ассисты и их доход нельзя складывать между строками: одна конверсия
может участвовать в нескольких строках. Линейный показатель делит её между
строками текущего среза и допускает суммирование внутри листа.
Сумма лидов Директа по нескольким целям может учитывать один визит несколько раз.
Связь по идентификатору в логах не гарантирует совпадения с сегментами людей
и кросс-девайс-отчётами интерфейса Метрики.

## Если возникла ошибка

- **Нет токена или счётчика:** проверьте `.env` в корне проекта.
- **401 / 403:** проверьте токен и права на счётчики и логин Директа.
- **Нет исходных файлов / несовместимый кэш:** переключитесь на `RUN_MODE=run`.
  Скрипт проверяет модель атрибуции, НДС, окно истории и наличие полей дохода.
- **Не найден модуль:** установите зависимости в том интерпретаторе,
  который выбран в PyCharm.

Папка `data/raw` содержит исходные TSV, `data/*.sqlite3` — рабочие базы,
`data/output` — готовые отчёты. Они не удаляются при упрощении проекта.

Для проверки кода без API:

```bash
python -m unittest discover -s tests -v
```
