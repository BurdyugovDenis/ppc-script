# Yandex Direct Export & Analyzer

Единый Python-проект для выгрузки детализированного отчёта из Reports API
Яндекс Директа и создания аналитического Excel по кампаниям и сегментам.

Проект поддерживает три сценария:

1. полный цикл: выгрузить CSV из API и сразу создать Excel;
2. проанализировать уже готовый CSV или XLSX;
3. только выгрузить CSV без анализа.

Исходные выгрузки не изменяются. Большие CSV обрабатываются потоково и не
загружаются целиком в память.

## Возможности

- автоматическая постраничная выгрузка Reports API;
- выбор периода, целей и модели атрибуции;
- отдельные метрики выбранных целей по флагу `--goal-breakdown`;
- отдельные листы по всем доступным срезам;
- сравнение сегмента с KPI кампании и KPI всех кампаний;
- безопасный режим CR/CPL без фиктивной выручки по умолчанию;
- независимое включение выручки, ДРР, ROMI и AOV;
- отклонения AOV, ДРР и ROMI от KPI кампании и всех РК;
- 95%-погрешность по интервалу Уилсона;
- разделение устойчивых выводов, гипотез и аномалий;
- поиск расходов без конверсий выше 3× KPI CPL;
- доля расхода сегмента в соответствующем скопе;
- исключение значений «Не определено» и аналогичных маркеров;
- IBM Plex Sans 10 pt, границы, фильтры, перенос текста, адаптивная
  ширина столбцов и высота строк;
- целочисленный формат кликов, конверсий, заказов и других счётчиков.

На листе `Категория запроса` одноимённые категории больше не смешиваются.
Они агрегируются по паре:

```text
Источник запроса × Категория запроса
```

В столбце `Источник запроса` отдельно выводятся `Автотаргетинг`,
`Ключевая фраза` и другие реальные типы условия показа из выгрузки.

## Структура проекта

```text
yandex-direct-analyzer-python/
├── main.py                    # единый запуск выгрузки и анализа
├── yandex_direct_report.py    # выгрузка Reports API в CSV
├── aggregate_export.py        # потоковая агрегация CSV/XLSX
├── build_report.py            # создание аналитического Excel
├── validate_report.py         # проверка итогов, структуры и оформления
├── requirements.txt
├── .env.example               # шаблон настроек без секретов
├── data/                      # локальные выгрузки, игнорируются Git
└── output/                    # готовые отчёты, игнорируются Git
```

## Требования

- Python 3.11 или новее;
- доступ к Reports API Яндекс Директа;
- OAuth-токен с правами на нужный рекламный аккаунт;
- Microsoft Excel, LibreOffice или совместимый просмотрщик для результата.

## Установка в PyCharm

1. Откройте папку `yandex-direct-analyzer-python` как проект.
2. Создайте виртуальное окружение:
   `Settings → Project → Python Interpreter → Add Interpreter → Virtualenv`.
3. Установите зависимости во встроенном терминале:

   ```bash
   python -m pip install -r requirements.txt
   ```

4. Скопируйте шаблон настроек:

   ```bash
   cp .env.example .env
   ```

5. Заполните `.env`. Реальный `.env` уже исключён из Git.

## Настройка `.env`

```dotenv
YANDEX_DIRECT_TOKEN=ваш_OAuth_токен
YANDEX_DIRECT_CLIENT_LOGIN=
YANDEX_DIRECT_GOAL_IDS=111111111,222222222
YANDEX_DIRECT_DATE_FROM=
YANDEX_DIRECT_DATE_TO=
YANDEX_DIRECT_OUTPUT_FILE=
```

Параметры:

- `YANDEX_DIRECT_TOKEN` — обязательный OAuth-токен;
- `YANDEX_DIRECT_CLIENT_LOGIN` — логин клиента для агентского аккаунта;
- `YANDEX_DIRECT_GOAL_IDS` — ID целей через запятую, максимум 10;
- `YANDEX_DIRECT_DATE_FROM` и `YANDEX_DIRECT_DATE_TO` — необязательный период
  в формате `YYYY-MM-DD`;
- `YANDEX_DIRECT_OUTPUT_FILE` — путь к CSV при отдельном запуске экспортёра.

Токен и клиентский логин не хранятся в исходном коде и не передаются в
аргументах командной строки. Если токен когда-либо был записан в публикуемый
файл или репозиторий, безопаснее перевыпустить его перед публикацией проекта.

## Полный цикл: выгрузка и анализ

```bash
python main.py --download \
  --date-from 2026-07-01 \
  --date-to 2026-07-31
```

Цели берутся из `.env`. При необходимости их можно временно переопределить:

```bash
python main.py --download \
  --date-from 2026-07-01 \
  --date-to 2026-07-31 \
  --goals 111111111 222222222
```

CSV будет сохранён в `data/`, после чего автоматически создастся:

```text
output/direct_report_analysis.xlsx
```

## Анализ готовой выгрузки

Если положить один или несколько CSV прямо в `data/`, достаточно запустить:

```bash
python main.py
```

Скрипт сам выберет самый новый непустой CSV из `data/` и выведет его путь
в консоль. Скрытые, пустые и недокачанные файлы игнорируются.

Конкретный файл всегда можно указать явно:

```bash
python main.py --input /полный/путь/direct_report.csv
```

Для XLSX с нужными данными не на первом листе:

```bash
python main.py --input /полный/путь/report.xlsx --sheet Данные
```

Свой путь результата:

```bash
python main.py \
  --input /полный/путь/direct_report.csv \
  --output /полный/путь/analysis.xlsx
```

## Только выгрузка CSV

```bash
python yandex_direct_report.py \
  --date-from 2026-07-01 \
  --date-to 2026-07-31 \
  --output data/direct_report.csv
```

Дополнительные параметры:

- `--attribution AUTO|LC|FCCD|LSCCD`;
- `--goal-breakdown` — отдельные столбцы конверсий и ценности по каждой цели;
- `--no-adjustment-names` — не запрашивать названия аудиторных корректировок.

## Запуск одной кнопкой в PyCharm

В `main.py` есть настройки по умолчанию:

```python
DOWNLOAD_BEFORE_ANALYSIS = False
INPUT_FILE = None  # автовыбор самого нового CSV из data/
OUTPUT_FILE = PROJECT_DIR / "output" / "direct_report_analysis.xlsx"

CALCULATE_REVENUE = False
CALCULATE_DRR = True
CALCULATE_ROMI = True
CALCULATE_AOV = False
AOV_FROM_CONVERSIONS = False
```

Варианты:

- положите любую готовую CSV-выгрузку в `data/` и запустите `main.py`;
- либо установите `DOWNLOAD_BEFORE_ANALYSIS = True`, заполните `.env` и
  запустите `main.py` для полного цикла.

Аргументы Run Configuration имеют приоритет над настройками в коде.

## Режимы финансовых метрик

Выгрузка Яндекс Директа может содержать `Доход` или `Ценность конверсий`, которые
для лидовых целей не являются реальной выручкой бизнеса. Поэтому по умолчанию
`CALCULATE_REVENUE = False`: в отчёт не попадают выручка, ДРР, ROMI и AOV, даже если число есть
в исходнике.

Для реальной выручки измените переключатели в начале `main.py`:

```python
CALCULATE_REVENUE = True
CALCULATE_DRR = True
CALCULATE_ROMI = True
CALCULATE_AOV = False  # True только для заказных целей
AOV_FROM_CONVERSIONS = False
```

Или включите метрики только на один запуск:

```bash
python main.py --revenue --drr --romi
```

Вариант с AOV-прокси, если каждая конверсия точно равна одному заказу:

```bash
python main.py --revenue --drr --romi --aov --aov-from-conversions
```

Каждый флаг имеет обратную форму: `--no-revenue`, `--no-drr`, `--no-romi`,
`--no-aov`, `--no-aov-from-conversions`. ДРР, ROMI и AOV не рассчитываются без включённой
выручки.

При включённых ДРР и ROMI добавляются отклонения от KPI кампании и всех РК
в процентных пунктах. Для AOV отклонение остаётся относительным: `AOV сегмента /
KPI AOV − 1`.

## Срезы аналитического Excel

Проект создаёт листы для доступных полей:

- название и тип кампании;
- тип условия показа;
- ключевая фраза;
- упоминание брендов в запросах;
- категория запроса с разделением по источнику запроса;
- тип соответствия;
- условие подбора аудитории;
- корректировки для целевой аудитории;
- номер и формат объявления;
- регион таргетинга;
- тип устройства;
- возраст, пол и пол × возраст;
- уровень платёжеспособности;
- тип площадки и вид размещения;
- название группы.

Для каждого сегмента рассчитываются расход, доля расхода, клики, конверсии,
CR, CPL, погрешность, KPI кампании, KPI всех РК и доступные финансовые метрики.

## Погрешность и устойчивость

Используется относительная полуширина 95%-интервала Уилсона. Вывод считается
устойчивым при погрешности не более 30%. Это не даёт ошибочного результата 0%
для случая `1 клик / 1 конверсия`.

Для строк без конверсий обычная корректировка не рассчитывается. Если расход
выше 3× соответствующего KPI CPL, строка отмечается как аномалия.

## AOV

Корректный AOV рассчитывается как:

```text
AOV = Выручка / Подтверждённые заказы
```

Если в выгрузке нет отдельного поля заказов, проект может использовать
конверсии как прокси. По умолчанию это отключено:

```python
AOV_FROM_CONVERSIONS = False
```

Включайте его только тогда, когда выбранные конверсии действительно соответствуют заказам:

```bash
python main.py --input report.csv --revenue --aov --aov-from-conversions
```

## Проверка результата

После создания Excel автоматически запускается `validate_report.py`. Он
проверяет:

- список листов и обязательные столбцы;
- контрольные суммы расхода, кликов, конверсий, выручки и заказов;
- формулы ДРР, ROMI, AOV и отклонений от общего KPI;
- отсутствие неопределённых сегментов;
- разделение категории запроса по источнику;
- числовые форматы, границы, IBM Plex Sans 10 pt и адаптивные размеры;
- отсутствие формульных ошибок;
- локальность групп внутри кампаний.

Если проверка не прошла, `main.py` завершится с ошибкой и выведет причину.

## Частые ошибки

### `YANDEX_DIRECT_TOKEN` не задан

Создайте `.env` рядом с `main.py` и заполните `YANDEX_DIRECT_TOKEN`.

### Не указаны цели

Заполните `YANDEX_DIRECT_GOAL_IDS` либо передайте `--goals`.

### Отчёт долго формируется

Большие периоды и детальные группировки могут давать миллионы строк. Экспортёр
автоматически ждёт готовности отчёта и загружает его страницами.

### AOV выглядит как число конверсий

Столбец `Количество заказов` использует конверсии как прокси только при
`AOV_FROM_CONVERSIONS = True`. По умолчанию этот режим выключен; не включайте его, если
конверсии не равны заказам.
